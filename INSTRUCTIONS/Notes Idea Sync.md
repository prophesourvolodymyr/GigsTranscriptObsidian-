# NOTES IDEA SYNC
## Documentation Workflow Instruction for AI

---

## 🎯 YOUR TASK

When the user provides you with **raw idea notes (N1)**, your job is to:

1. **Read all files** in the specified `/NOTES/[Folder Name]/` directory
2. **Analyze the raw ideas** and understand the core concept
3. **Create a comprehensive N2 white paper** that explains:
   - What's technically possible
   - How it would work
   - Implementation approach
   - What's realistic vs. aspirational

---

## 📝 FILE NAMING CONVENTION

### **N1 = Raw Ideas** (what user writes)
- Format: `[Topic] Orig.md` or `N1 [Topic].md`
- Content: Unstructured thoughts, bullet points, quick notes

### **N2 = Detailed Specification** (what you create)
- Format: `N2 [Topic] White Paper.md`
- Content: Comprehensive, structured, technical documentation
- Save in: Same folder as the N1 files

---

## 🤖 WHAT TO DO

When user says:
> "Read my notes in @[Folder Name] and create N2 white paper"

**You should:**

1. **Read** all files in `/NOTES/[Folder Name]/`
2. **Read** any examples in `/NOTES/Examples/` if they exist
3. **Analyze** what's being proposed
4. **Think deeply** about feasibility and implementation
5. **Create** a comprehensive N2 document with:
   - Executive summary
   - Technical breakdown
   - What's possible and how
   - Implementation details
   - Examples and structure
6. **Save** as `N2 [Folder Name] White Paper.md` in the same folder

---

## 💡 YOUR APPROACH

- ✅ **Ultra-think** - Don't rush, think deeply about every aspect
- ✅ **Be creative** - Expand on ideas, don't just transcribe
- ✅ **Be comprehensive** - 8,000+ words is fine if needed
- ✅ **Be realistic** - Explain what works and what doesn't
- ✅ **Structure well** - Clear sections, examples, diagrams
- ✅ **Think ahead** - Consider implementation challenges

---

## 📋 DOCUMENT STRUCTURE

Your N2 white paper should include:

```markdown
# N2 [Topic] White Paper

## Executive Summary
[What this is about - 2-3 paragraphs]

## 1. [Main Topic Area 1]
[Detailed breakdown]

## 2. [Main Topic Area 2]
[Detailed breakdown]

## 3. Technical Implementation
[How it would actually work]

## 4. What's Possible vs. What's Not
[Realistic assessment]

## 5. [Additional relevant sections]
[Based on the topic]

## Conclusion
[Summary and next steps]
```

---

## 🎯 KEY PRINCIPLES

**DO:**
- Read EVERYTHING in the folder
- Think beyond what's written (creative expansion)
- Provide technical depth
- Explain trade-offs clearly

**DON'T:**
- Just reformat the notes (add value!)
- Skip technical details
- Make it too brief (go comprehensive)
- Assume everything is possible (be realistic)

---

## 🚀 QUICK REFERENCE

**Input:** Raw idea notes (N1)
**Output:** Comprehensive white paper (N2)
**Naming:** `N2 [Topic] White Paper.md`
**Location:** Same folder as N1 files
**Approach:** Ultra-think + Creative + Comprehensive + Realistic

---

**Remember:** Transform unstructured thoughts into professional, implementable documentation.
